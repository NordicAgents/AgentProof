\section{Related Work}
\label{sec:related}

\paragraph{Runtime agent safety.}
NeMo Guardrails~\citep{nemo_guardrails}, Guardrails AI~\citep{guardrails_ai},
LlamaGuard~\citep{llamaguard}, and Rebuff~\citep{rebuff} enforce safety at the
point of LLM output or tool call, catching violations only when the offending
path runs; ToolEmu~\citep{ruan2024toolemu} and
AgentDojo~\citep{debenedetti2024agentdojo} measure agent risk by executing
behaviors. Our analyzer is complementary: it analyzes topology before deployment
and decides which runtime monitors are needed (Section~\ref{sec:pruning}).

\paragraph{Concurrent agent-policy systems.}
A concurrent line of work enforces policies at the tool-call boundary with
formal machinery: Agent-C compiles temporal safety specifications to constraints
checked at generation time with conformance guarantees~\citep{kamath2026agentc};
AgentSpec provides a runtime-enforcement DSL~\citep{wang2025agentspec}; ClawGuard
and SecureClaw interpose rule sets and authorization boundaries against prompt
injection~\citep{zhao2026clawguard, ma2026secureclaw}; PolicyGuard trains a
guardrail model for trajectory-level violation
detection~\citep{wen2025policyguard}; and AgentFlow builds cross-framework agent
dependency graphs for static security analysis at
scale~\citep{wang2026agentflow}. Two bound our contribution sharply. Agent-C
already enforces temporal specifications with conformance guarantees, so we claim
no novelty for temporal enforcement; AgentFlow already builds richer
cross-framework dependency graphs over $5{,}399$ programs, so we claim none for
cross-framework graph construction or scale. What remains ours is the measurement
neither performs: \emph{how faithfully} such extracted models correspond to the
code they abstract. AgentFlow reports no validation of its graphs against
reference models; our result is that on public code this is not a formality but
a dominant term in the error budget.

\paragraph{Empirical characterizations of agent defects.}
Recent studies catalogue where agent systems break: a defect taxonomy from
developer discussions~\citep{ning2024agentable}, nine root causes across
${\sim}1{,}026$ orchestration bugs~\citep{xue2025bugs}, and $221$ vulnerabilities
spanning fourteen types~\citep{shen2025securitydebt}. We ask not \emph{which}
defects occur, but \emph{how reliably a static analyzer can recover the
behavioral model it needs to find them}.

\paragraph{Model checking and workflow soundness.}
Classical model checkers---SPIN~\citep{holzmann1997spin},
NuSMV~\citep{cimatti2002nusmv}, CBMC~\citep{cbmc}---verify the same class of
properties but require manual translation into Promela/SMV/annotated~C. Our
policy semantics follow LTL on finite traces~\citep{degiacomo2013ltlf}, with
monitoring in the style of JavaMOP~\citep{javamop} and three-valued runtime
verification~\citep{bauer2011ltl3}. Business-process soundness for Petri
nets~\citep{vanderaalst2011bpm} and BPMN~\citep{dijkman2008bpmn} studies
analogous reachability properties over visual notations rather than the
programmatic APIs agent frameworks expose.

\paragraph{Audits of static analysis.}
Industrial experience established that false-positive and actionability rates,
not detector cleverness, decide adoption~\citep{bessey2010coverity,
johnson2013static, sadowski2018lessons}. Ours is the agent-workflow instance of
that genre, and adds a failure mode those studies did not face: the \emph{model
extraction} step carries its own large share of the error budget, so
non-actionability must be apportioned between extractor and policy rather than
attributed wholly to the checks. Broader agent-safety work emphasizes alignment,
capability evaluation, and governance~\citep{anthropic_rsp, metr,
gabriel2024ethics}; our contribution is orthogonal and empirical. The reported
rates describe a fixed convenience-corpus audit, not population prevalence.
