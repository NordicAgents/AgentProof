\section{Introduction}
\label{sec:introduction}

Large language models are increasingly deployed as autonomous agents that call
external tools and APIs~\citep{schick2024toolformer, yao2023react}, and
orchestration frameworks structure this behavior as explicit \emph{workflow
graphs}: LangGraph~\citep{langgraph_docs}, CrewAI~\citep{crewai_docs},
AutoGen~\citep{wu2023autogen}, and Google ADK~\citep{google_adk_docs} represent
computation steps as nodes and allowable transitions as edges. Safety
enforcement remains almost entirely a \emph{runtime} concern: NeMo
Guardrails~\citep{nemo_guardrails} and LlamaGuard~\citep{llamaguard} filter
individual calls at execution time, detecting a violation only when the
offending path is exercised.

Some defects, however, are topological. Consider an email-triage agent whose
developer adds a \texttt{draft\_response} node but forgets to connect it to
\texttt{send}: normal-priority emails silently halt at a dead end. A runtime
guardrail cannot catch this unless that path runs, but a static analysis of the
graph flags it and emits a witness trace. Classical model
checkers~\citep{clarke1999modelchecking, holzmann1997spin, cimatti2002nusmv}
verify such properties, but require hand-translation into Promela or SMV. For
conventional static analyzers, adoption is decided not by detection power but by
the rate of actionable findings~\citep{bessey2010coverity, johnson2013static,
sadowski2018lessons}; the analogous question for agent workflows---how often
these graphs contain the defects static checks target---has received far less
measurement.

\paragraph{Thesis.}
Answering it requires a prior question: \emph{can we trust the graph?} A static
check is only as credible as the behavioral model an extractor recovers from
source, and on public agent code that extraction is lossy---it manufactures
false flags and hides true defects at once. A second question is equally
necessary: \emph{does the policy govern this workflow?} Our audit shows that
the answer is check-family dependent. A graph-substitution survival test
attributes 68 of 72 non-actionable structural findings to extraction, while it
attributes 94 of 112 non-actionable human-gate findings to an inapplicable
blanket approval policy. These counts should not be pooled into a universal error rate: the
aggregate is determined by the chosen mix of checks, frameworks, and files.
More importantly, the reverse audit finds a different boundary. All 12
source-audited human-gate violations escape the mined pipeline; nine remain
invisible even in a source-reconstructed graph because the regulated effect
lives inside a node body. Static verification of agent workflows is therefore a
measurement problem over three distinct objects: extraction fidelity, policy
applicability, and abstraction coverage.

\paragraph{Study.}
We use it as a measurement instrument on 922 extracted
file-level graphs mined from public GitHub across the four frameworks---a
search-ranked convenience corpus, not a probability sample---and validate a
quota-selected 119-graph sample against \emph{LLM-reconstructed reference
graphs} from an independent, adversarially cross-checked LLM pass. These are
\emph{LLM-assisted exploratory labels}, not human-validated ground truth; a
two-human validation protocol and locked samples are provided, and we bound our
current claims accordingly.

\paragraph{Three audit quantities, not one prevalence.}
A pooled rate conflates distinct quantities, so we report separately:
flag-level precision; observed structural defects, a topological judgment; and
observed human-gate policy violations, a normative judgment under one policy
fixed before case labeling (Table~\ref{tab:estimands}). Because neither the
GitHub corpus nor the 119-file validation set is a probability sample, these are
descriptive audit proportions, not population-prevalence estimates.

\paragraph{Contributions.}
\begin{itemize}\itemsep1pt
  \item \textbf{A cross-framework extraction-fidelity audit} with matched,
  provenance-disambiguated instruments and a corrected-extractor ablation. It
  localizes extraction error to structural checks instead of treating all
  findings as one population.
  \item \textbf{Symmetric audits of findings and misses.} Holding checks fixed
  while swapping mined for reconstructed graphs separates extraction from
  check-side effects; applying the same test to source-audited violations shows
  when the graph vocabulary itself omits the regulated behavior.
  \item \textbf{A separation of policy applicability from graph fidelity.} A
  policy fixed before case labeling exposes violations outside both original
  flag universes and \emph{placebo} human gates that make graph-only evaluation
  overstate oversight.
\end{itemize}
The graph\,$\times$\,DFA mechanism is an audit instrument and a conditional
design implication, not a fourth contribution: without independently
established event coverage, it withholds \texttt{safe}
(Section~\ref{sec:results}).
