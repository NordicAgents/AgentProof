\section{Base-Rate Study on Public GitHub Workflows}
\label{sec:realworld}

To estimate defect base rates on independently authored workflows---and to
measure extractor fidelity on code we did not write---we mined public GitHub
repositories across all four frameworks. We state the population precisely:
\emph{public GitHub files matching framework-specific code searches}, not
production deployments. The unit of analysis is one source file mapped to one
\emph{extracted file-level graph}; some files hold multiple executable roots,
only task declarations, or fixtures, so a fully executable-workflow-root unit
is future work. We census the population below and report all prevalence
figures as \emph{LLM-assisted exploratory estimates}, not ground truth.

\paragraph{Mining and corpus census.}
Using GitHub code search (\texttt{gh} CLI, July 2026, newest pinned commit
2026-07-11, with per-framework query sets and per-repository caps) we streamed
each candidate repository through clone, extraction, and cleanup. After removing
one repository of our own test fixtures (8 files; a contamination detected
during revision and excluded from every number), the corpus is \textbf{922
extracted file-level graphs} from 252 distinct repositories (LangGraph~400,
AutoGen~359, CrewAI~113, ADK~50), with provenance recorded as repository,
commit SHA, and file path. Mined graphs are small---median 2 non-sentinel nodes
(mean~3.9)---and predominantly static linear pipelines. The corpus is
\emph{not} mostly applications: 32\% of files carry tutorial/test/demo-style
names, 48 topology groups are topologically identical duplicates across
repositories (170 redundant graphs, retained but reported), and a source-level
classification of the validation sample (below) found 44\% tutorial or course
material, 17\% toy demos, 7\% test files, and 33\% application-like code. We
therefore report prevalence both pooled and stratified by this classification.

\paragraph{Reference graphs and validation.}
On a stratified 119-graph sample from 87 repositories (LangGraph~40, CrewAI~20,
AutoGen~35, ADK~24) we ran two independent LLM-agent passes (Claude Opus~4.8
under a multi-agent harness; all outputs released). First, an agent
reconstructed a reference graph from source alone, blind to the extractor's
output and following its node-id conventions; we score node/edge
precision--recall and node-kind accuracy against these \emph{LLM-reconstructed
reference graphs} (reconstruction confidence: 77 high, 33 medium, 9 low).
Second, every flag was triaged from source
(\textsc{real}/\textsc{extraction-artifact}/\textsc{intentional}) and an
adversarial verifier attempted to overturn each label (4.6\% overturned;
unresolved labels recorded as \textsc{arguable}). We state the limitation
squarely: reference graphs are LLM reconstructions, not human annotations, and
both passes share a model family. Results are stable on the high-confidence
subset (edge recall 0.67 vs.\ 0.65 overall), every triage label carries a
source-line justification that survived an adversarial pass, and a revision
re-audit overturned one label of 16 re-examined. \textbf{Two-annotator
independent human validation was not performed; it is required future work,
and the protocol and samples are staged.} We report Wilson 95\% CIs for
proportions and repository-clustered bootstrap CIs (10{,}000 resamples) for
means, since workflows from one repository are not independent.

\paragraph{Extraction fidelity is the bottleneck.}
Node detection stays strong and stable across instruments (v2 overall
$P{=}0.89$, $R{=}0.85$; v1 $0.91/0.85$), but edge recall and node-kind accuracy
are the bottleneck and are strongly framework-dependent
(Table~\ref{tab:realworld_fidelity}): the corrected instrument recovers only
0.36 of ADK's edges---whose nested \texttt{SequentialAgent}/
\texttt{ParallelAgent} composition, and AutoGen's participant lists with dynamic
speaker selection, encode topology \emph{implicitly}---versus 0.82 on LangGraph,
whose edges are explicit. On LangGraph the dominant remaining error is instead
node-kind (\texttt{tool}$\rightarrow$\texttt{llm}: nodes invoking tools in their
body with no declared binding; kind accuracy 0.67). This is a property of the
static AST fallback used at scale, not of the runtime extractors that read the
compiled framework object (for ADK the runtime graph is far richer, 16 vs.\
${\sim}5$ edges); realizing that ceiling would require sandboxed execution of
untrusted code, which we do not attempt. A post-hoc audit
demonstrates the diagnosis \emph{causally}: the extractor silently dropped
conditional edges declared through LangGraph's common three-argument
\texttt{add\_conditional\_edges} form. Fixing that one bug and re-extracting at
the identical pinned commits---the check algorithms untouched---raises LangGraph
edge recall from 0.68 to 0.82 (the v1$\rightarrow$v2 shift in
Table~\ref{tab:realworld_fidelity}) and removes roughly a quarter of the
structural flags (314$\rightarrow$239 flagged workflows; unreachable-exit flags
86$\rightarrow$32), directly confirming extraction, not the checks, as the
bottleneck. Both instruments are released.

\paragraph{Flag precision on extracted graphs.}
Distinct from prevalence, we ask what fraction of the checker's \emph{flags} on
extracted graphs are genuine. The as-mined study raised 186 flags on 114
file-level graphs; adversarial triage confirmed 2 as genuine (both missing
human gates on sensitive workflows), classifying 42\% as extraction artifacts
and 50\% as intentional design (full triage breakdown in the supplement). This
is a workflow-level PPV of $2/114 = 1.75\%$ $[0.48,6.17]\%$
(repository-clustered bootstrap $[0.00,4.59]\%$) and a flag-level confirmed PPV
of $2/186 = 1.08\%$ $[0.30,3.84]\%$. Because flags are correlated---one missing
edge fires several structural checks---we also dedup to root cause
($186\rightarrow161$ flags, 25 structural collapsed; $2/161 = 1.24\%$
confirmed). Counting all 12 \textsc{arguable} labels pessimistically as genuine
bounds the flag-level rate at $14/186 = 7.53\%$ $[4.54,12.24]\%$
($14/161 = 8.70\%$ deduped), so the identification rate lies in
$[1.08\%, 7.53\%]$. \emph{None of the 72 structural flags was confirmed
genuine} (0 genuine, 1 arguable; CI $[0,5.1]\%$), and structural flags are
almost entirely a LangGraph phenomenon---partly \emph{by construction}, since
the other three extractors emit connected topologies and cannot produce a dead
end or unreachable exit. This as-mined 186-flag universe (genuine${=}2$) is
\emph{distinct} from the reconstructed-graph re-run that yields the four
confirmed estimand cases below (one of them structural); we never pool the two.

\paragraph{Defining a defect.}
Flag triage cannot see false negatives: a defect the lossy extractor never
surfaces is absent from the flag universe entirely. We therefore re-ran every
check on the 119 LLM-reconstructed reference graphs---which can express dead
ends and unreachable exits for all four frameworks---and adversarially triaged
the results, recovering two genuine defects the extracted study missed. We
separate two kinds of finding the pooled count conflated. A \emph{structural
defect} is a genuine topology error (unreachable exit, dead end, mis-wired
router)---a property of the graph, confirmed on the reference graph. A
\emph{human-gate policy violation} is a normative judgment, not a structural
fact: a side-effecting or irreversible tool (SQL execution, payment, external
write) is reachable along some path with no intervening \textsc{human}
checkpoint, judged against an explicit policy---\emph{no irreversible tool
without a preceding human gate}---and it would not appear under a permissive
policy. We report each as a \textbf{distinct estimand} and their union
(\emph{composite}) only as a heterogeneous secondary summary.

\paragraph{Three estimands and post-stratification.}
Table~\ref{tab:estimands} reports all three. The one structural defect is a
router mis-wiring in an ADK SQL agent (application-like): $1/119$
$[0.15,4.61]\%$. The three policy violations are a LangGraph chatbot whose
SQL-executing tool is reachable with no human gate, and a CrewAI workflow and
an ADK payment agent flagged for missing human presence on side-effecting
paths: $3/119$ $[0.86,7.15]\%$. The composite is $4/119$ $[1.31,8.32]\%$. The
sample over-represents ADK---20\% of the sample but 5.4\% of the corpus
($50/922$)---and ADK carries 2 of the 4 cases (per-framework composite:
LangGraph 1/40, CrewAI 1/20, AutoGen 0/35, ADK 2/24), so the unweighted rate
overstates. Re-weighting each stratum to its corpus share (repository-clustered
bootstrap) lowers every estimate: structural $0.23\%$ $[0.00,0.80]$, policy
$1.92\%$ $[0.00,4.85]$, composite $\mathbf{2.15\%}$ $[0.20,5.12]$, against the
unweighted validation-sample composite of $3.36\%$. We treat the
post-stratified figures as the corpus-facing estimate and $3.36\%$ as a
validation-sample statistic only. Three of four observed cases occurred in
application-like files ($3/39 = 7.7\%$ vs.\ $1/80 = 1.3\%$ in tutorials, demos,
and tests), but the sample is too small to establish a stratum difference
(Fisher exact $p{=}0.10$; OR~6.58 $[0.66,65.5]$, the interval spanning~1); we
report the association descriptively only and make no claim that defects
concentrate where the stakes are highest.

\paragraph{Risk-aware gating.}
The blunt human-presence check fires on 91\% of mined file-level graphs with
only 2 of 113 firings genuine---uninformative as a detector, motivating the
risk-aware \emph{human-gate coverage} check: flag only when a sensitive tool
(destructive/write/exec/communication/financial, by a keyword lexicon over
bound tool names) is reachable without a \textsc{human} gate. On the 922 mined
graphs it fires zero times---a statement about extracted \emph{declarations},
not the code: no mined graph declares a sensitive binding, while source-level
classification finds side-effecting tools in 32 of 119 sampled workflows,
invisible to the extractor through the \texttt{tool}$\rightarrow$\texttt{llm}
kind error. On the reconstructed graphs, where bindings are recovered from
source, the same check fires three times and one firing is the genuine
SQL-gate defect above. The lexicon is \emph{correct relative to its
declared-tool abstraction}; its recall is bounded by extraction fidelity---the
paper's central diagnosis.

\paragraph{Threats to validity.}
\label{par:threats}
\emph{Construct:} the composite estimand unions a structural graph property with
a policy judgment, which is why we report the two separately.
\emph{Internal:} reference graphs and triage labels come from LLM passes sharing
a model family, so correlated errors are possible; we report reconstruction
confidence, adversarial overturn rates, and a re-audit, but these are not
independent human judgments. \emph{External:} the population is public GitHub
files, not production deployments, and the unit is a file-level graph, so
results may not transfer to executable workflow roots or private code.
\emph{Sampling:} the validation sample is stratified and over-represents ADK; we
post-stratify to corpus composition, but small per-stratum counts leave wide
intervals. \emph{Label reliability:} no human validation has yet been performed;
a two-annotator independent protocol with staged samples is required future
work. Accordingly we frame every prevalence number as an LLM-assisted
exploratory estimate, not ground truth.
